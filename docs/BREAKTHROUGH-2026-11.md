# 突破路线：从「能出 mp4 的研究仓库」到「可嵌入的角色运行时」

> 2026-11-12 · 基于全网调研 + 仓库体检 + 线上流量数据 · 本文是判断文档，不是功能清单
> 结论先行，证据在后。**不做什么**和「做什么」同等重要。

---

## 0. 一句话判断

**项目不是技术不行，是「最稀缺的性质没有交付给别人」。**

codeavatar 真正独一无二的东西不是「能做口播视频」（这件事 2026 年有几十个开源方案，成本已低到 $0.04/成品分钟），
而是：**角色 = 一份纯文本 JSON，表演 = 一组数值，渲染 = 一个纯函数**。
因此它天然具备整个赛道都给不了的性质——零 GPU、零模型权重、零肖像权/声纹权、零 deepfake 合规负担、
确定性可复现、可 git diff、可 CI、可离线、可嵌进任何网页。
**注意（§7 修订）：这一串是实现性质，不是用户价值，不能拿去当宣传主文案。**

但仓库把这组性质锁在 `private: true` + Python CLI + Remotion 视频渲染背后。
别人拿不到「运行时」，只能拿到「一个要装两套工具链才能跑的脚本」。
**突破口就是把这组性质变成可被第三方消费的形态。**
原文此处写过「而不是继续提升视频质量」，这句判断已被用户纠偏删去：
**分发与可运行性解决的是「别人拿不到」，最终目标仍然是提升效果**；
如果某一天更重的技术方案能把画面做得更好，就该用它（见 §7）。

### 1.3 渲染器的隐藏资产（体检里唯一的好消息）

`packages/anchor-core/src/FaceTraced.tsx` 全文件：
- 无 `window` / `document` / `useEffect` / `useState`；
- 无 `useCurrentFrame` 或任何 Remotion API；
- 依赖只有 `React`（`useId`）+ 三个纯计算模块 + 角色 JSON。

**推论**：它可以用 `react-dom/server` 的 `renderToStaticMarkup` 直接 SSR 成纯 SVG 字符串。
也就是说，同一个渲染器既能出 mp4，也能零构建、零 GPU 地变成网页里活的角色。
这是整个突破路线的技术地基——而且**已经具备，不需要重写**。

## 2. 全网调研结论（2026-11-12，跨源）

### 2.1 赛道格局：模型层已经卷完，价值在往「产品/流程」迁移

| 路线 | 代表 | 现状 |
|:--|:--|:--|
| 口型重绘 | Wav2Lip / MuseTalk 1.5 / LatentSync 1.6 | 实时门槛已过（MuseTalk 30fps@256²），但嘴部画质与权重许可是坑 |
| 扩散说话头 | EchoMimic V3 / LiveAvatar / Wan2.2-S2V / InfiniteTalk | 质量最高；LiveAvatar 峰值 61.4GB 显存，长视频仍靠 5–10s 分段拼接 |
| 3DGS 驱动 | LivePortrait(19.5k★) / TaoAvatar / GUAVA | 实时+多视角，但依赖人脸识别组件（InsightFace 非商用） |
| 全栈整合 | LiveTalking(9.6k★) / OpenAvatarChat / AvatarAI | 事实标准正在形成，端到端约 2.2s，亚秒全双工仍未解决 |

**成本对照**：FlashHead Pro ≈ $0.04/成品分钟，LongCat ≈ $1–4/分钟，差 100 倍；
HeyGen 类 SaaS 已被压到 $22–67/月。国内京东/百度数字人平台**免费开放**，淘宝 499 元/月。

**行业判断（多方一致）**：开源解决的是模型层，不是产品层；
「卖标准化数字人」已无溢价（阿里云 2026 年宣布虚拟数字人产品退市即为例证）。
真正的增量转向 ① 高合规行业私有化 ② 长内容/多语种产线 ③ 数字人作为 Agent 的执行界面。

### 2.2 监管在 2026 年变成硬门槛 —— 反而是本项目的红利

- 中国《直播电商监督管理办法》2026-02-01 施行，AI 主播须显著标识；
- 《人工智能拟人化互动服务管理暂行办法》2026-07-15 施行，循环录播无人直播被集中清理；
- EU AI Act 50(4) 自 2026-08-02 生效，deepfake 部署者必须披露；50(2) 要求 2026-12-02 前完成机器可读标识；
- 开源模型普遍存在「代码 MIT / 权重非商用 / 训练数据集学术用途」三层许可冲突（Wav2Lip 明确禁商用，LivePortrait 依赖的 InsightFace 非商用）。

**codeavatar 是纯插画角色、不使用真人素材、不生成拟真人脸、不克隆声纹**，
天然落在这些条款的适用范围之外，且没有权重许可尽调成本。
这一点在 README 里完全没提 —— 是被浪费掉的最强差异化。

### 2.3 最接近的商业形态，反证了空白

调研里唯一走「轻量矢量角色 + 音素口型 + 可嵌入」路线的是 Rive 生态
（如 Mascotbot SDK：Rive 状态机 + viseme 数字输入 100–118 + ElevenLabs 时间戳）。
但它是**闭源私有 npm registry + API key**，且要求设计师手工在 Rive 里绑骨、分层、做状态机。

即：**「开源 + 零依赖 SVG + 从一张设定稿自动建角 + 不需要设计师绑骨」的位置是空的。**
这正是 codeavatar 已经踩到、却没有说出口的位置。

### 2.4 分发侧：冷启动的可复现规律

- star 是发现信号不是采用信号；GitHub Trending 按**窗口内新增速度**排名，不按总量；
  因此要把曝光压缩进 24–48 小时形成单一尖峰，分散两周的每个小尖峰都跨不过阈值。
- 渠道 ROI 排序：仓库转化工程（乘数）> Show HN > 定向 subreddit > Product Hunt > 中文周刊/HelloGitHub > awesome 列表。
- **0 星本身就是转化障碍**：需先靠真实关系网络跨过 100–300 星，之后自然渠道才成立。
- 明确无效：买星（ICSE 2026 论文：约 600 万颗假星、被标记仓库 90.42% 已被删）、跨版复制文案、过早多语言铺开。
- 关键顺序：**先修 README/可跑性/入口，再发射**。曝光打在漏斗断裂的仓库上是纯浪费。

## 3. 根因判断（三层）

1. **分发层（表象）**：没有导流，只有 1 个真人到达。→ 但这不是最该先修的。
2. **转化层（真因）**：即便有人到达，也看不到效果、装不起来、装完不知道能拿走什么。
   README 劝退 + 零视觉证据 + 零可消费入口，构成教科书级漏斗断裂。
3. **形态层（根因）**：项目把自己定义成「成片生成器」，而它最稀缺的能力是「可嵌入的角色运行时」。
   定位错一层，后面所有分发和内容都会打偏。

**所以第一刀不是写推广文，也不是加角色，而是改变「别人能拿走的东西」的形状。**

## 4. 突破口：Avatar-as-Code 运行时

### 主张

> **⚠️ 2026-11-12 修订（用户纠偏）**：本节最初写的技术自述式定位
> 「零模型、零 GPU、零肖像权、零 deepfake 合规负担」**已被否掉**，见 §7。
> 那是一句写给同行看的实现说明，不是用户价值。保留在此仅作判断轨迹，
> **不得再用作 README / demo / 发布物料的主文案**。

对外定位改为讲效果与用途：

> **给你的设定稿一张会动的脸。** 一个角色会说话、会做表情，口播视频、网页、
> Agent 回答里用的都是同一张脸。表情和口型是数字，改一个值就换一张脸，
> 不用重画、不用重录。

「Avatar-as-Code / 角色 = 可 diff JSON / 渲染 = 纯函数」仍是正确的**内部架构判断**，
但它解释的是「为什么改起来这么直接」，不是用来劝人用的卖点。

### 主突破（P0，必须做）

**拆出零依赖运行时**：`renderSvg(char, pose) → SVG 字符串`，去掉 Remotion 强绑，
提供 npm 包 + CDN + 单文件 HTML demo（打开即说话）。让「装一个依赖、写三行代码」取代「clone 全仓」。

### 支撑突破（P1/P2，形成别人离不开的理由）

| 编号 | 内容 | 为什么是突破口 |
|:--|:--|:--|
| **P1** | **自动建角**：把 noF 的「手量五区」变成浏览器点 5 下 → 生成 PRESETS | 修掉「零人工」的诚信缺口，更是第三方能否造自己角色的唯一门槛。没有它，生态永远只有 2 个角色 |
| **P2** | **Agent 接口**：MCP server / 一行 script，Agent 输出文字 → 角色开口 | 2026 行业共识「数字人就是看得见的智能体」；GPU 方案无法给每个 Agent 回答配化身，零成本方案可以。也是 WorkBuddy 生态内的天然分发 |
| **P3** | **分发工程**：README 首屏重写 + hero GIF + 在线 demo + topics/description + v0.2 release + 48h 脉冲 | 转化乘数；必须在 P0 完成后做，否则流量白来 |
| **P4** | **合规叙事**：明确「非生成式 / 非 deepfake / 无肖像权声纹权 / 无需 AI 标识」 | 把监管从行业成本变成我们的卖点，面向教育/政务/金融私有化 |

### 明确不做（同样重要）

- **不卷写实 / 不接扩散模型**：赛道已卷完且成本崩塌，接上去等于丢掉唯一差异。
- **不做直播 SaaS / 电商带货**：渗透率超 60%、京东百度免费、监管成本双杀，红海。
- **不追求「更多角色」**：在别人能自己造角色之前，角色数量是虚荣指标。
- **不在漏斗修好前做大规模推广**：按冷启动规律，分散曝光必然浪费。

## 7. 风险与红线

- **唯一事实源硬纪律**：运行时必须复用 `FaceTraced`，不许另写一份 SVG 渲染器；
  否则两份实现漂移，golden 基线与全部门禁失效。
- **零漂移**：解耦不得改变 no1/no4 输出，`identity_check no4` 15 帧必须逐字节一致。
- **诚实标注**：节奏估计模式、手量建角、能力边界都要如实写；这是项目已有的好传统，不能为推广牺牲。
- **合规表述**：只陈述「本项目不使用真人素材、不生成拟真人脸」这类事实，
  不代替第三方做法律结论，不宣称「免监管」。

## 执行记录

### 2026-11-12 · P0 第一刀 + 可发布运行时 + 分发工程（首屏）

**P0 主突破：已完成并通过验收。**

- `renderFaceSvg` 落地，运行时零依赖；`FaceTraced` **一行未改**，唯一事实源纪律未破。
- 单文件 `demo/runtime.html`（1.1 MB，18 帧）在 headless Chrome 中实测渲染正常，
  角色清晰可见，无 React / Remotion / 构建 / 网络请求。
- **视觉等价：0 / 3,072,000 像素差异**（`tools/runtime_parity_check.py --char noF`）。
  做法是新增 `RuntimeGrid` composition，让参考图与校验图都由 `remotion still` 输出，
  页面骨架 / Chrome 参数 / CDP 截图管线完全相同，唯一变量是 SVG 来源。

**parity 排查记录（保留，避免后人重复踩坑）。**

最初拿「独立 HTML 的 headless 截图」直接和 Remotion 图比，得到 6.156% 差异、最大通道差 107，
误判为渲染不等价。逐层定位后确认是两类**页面级**变量，与 SVG 内容无关：

1. Remotion 注入全局 `* { box-sizing: border-box }`（`remotion/dist/cjs/default-css.js`）。
   独立页面用默认 `content-box` 时，每格 1px 边框外扩、裁剪区错 1px。补齐后
   边框像素从 x=640 回到 x=639，完全对齐。
2. Remotion 用 `openBrowser` 启动的 Chrome + CDP `Page.captureScreenshot({
   fromSurface:true, optimizeForSpeed:true })`，启动参数**不含** `--disable-gpu`；
   `chrome --headless --screenshot --disable-gpu` 是另一条光栅路径。
   `tools/runtime/screenshot.mjs` 复刻了这条管线（含 `--force-color-profile=srgb`），
   大差异（>16）从 22,672 降到 10,512。

复刻后仍剩 5.761% 的 ±1～2 通道差异；抽样 **100% 的大差异落在参考图颜色边界上**，
且重生成参考图与旧图逐像素一致（排除陈旧产物）。结论：来自不同页面合成层的 Skia 舍入，
不是几何或内容错位。**因此改为同管线断言**，跨管线对比降级为「仅记录、不判定」的
`--cross-check` 报告，不靠放宽阈值蒙混过关。

**P0 第二阶段：可发布运行时包 `codeavatar-runtime@0.2.0`。**

- 三种入口 `dist/index.mjs` / `index.cjs` / `standalone.js`（219 / 603 / 220 KB），
  React 与 `react-dom/server.browser` 全部打进产物，运行时零依赖。
- 合规红线：角色美术资产不是 MIT，不能随包再分发。构建期依赖 esbuild tree-shaking
  去掉 `CHARS`，并由 `build.mjs` 检查产物不含角色颜色 / `CHARACTER_DATA` / Remotion 引用。
- `verify.mjs` 结果：`standalone` 在裸上下文（无 React / 无 Remotion / 无 require）可用；
  三入口 6 帧 SVG 逐字节一致；**发布产物 == parity SSR 帧 == 已验证的 React DOM 渲染**；
  `d.ts` 的 Pose 15 项与 `POSE_RANGES` 一致；无资产泄漏。

## 7. 宣传叙事纠偏（2026-11-12，用户明确反馈）

### 反馈原文（关键句）

> 「其实你这个宣传做得就不好……你这是写给专业的人看的，但是实际上大部分人并不关心
> 你用没用 Remotion、有没有 React。而这也不是我们需要去限制的，如果需要，我们也可以用。
> **目的是提升效果。而不是缩减资源**」

此前 `demo/runtime.html` 首屏写的是「这个页面没有 React、没有 Remotion、没有构建步骤、
没有 GPU……」，README / 包 README 也把「零依赖 / 零 GPU / 零模型权重」放在最显眼处。

### 判断错在哪

| 错处 | 说明 |
|:--|:--|
| 把实现手段当用户价值 | 「不用 React」是作者省了事，不是使用者得到了什么 |
| 把取舍包装成能力边界 | 写「没有 GPU」像在承诺永不使用，实际只是当前做法 |
| 受众错位 | 技术同行会心一笑，普通用户 10 秒内得不到任何理由留下 |
| 目标漂移 | 「缩减资源」被写成了目标，而项目目标始终是**提升效果** |

### 产品原则（长期纪律）

1. **技术选择服务于效果。** 需要 React / Remotion / GPU / 模型 / 更重管线才能让画面更好，
   就用；不为守住「零依赖」这类标签牺牲画面。
2. **对外只讲能做什么、能拿到什么效果**：会说话、会做表情、同一张脸跨视频/网页/Agent、
   改数字就换脸、可回退、批量结果一致。
3. **零依赖 / 零 GPU / 同管线 parity 仍保留**，但位置是「实现说明 / 验收证据 / 工程纪律」，
   不进首屏、不做主标题、不进 hero 图。
4. **每次改物料自检**：首屏前两屏里有没有出现普通人看不懂或不在乎的技术名词。
