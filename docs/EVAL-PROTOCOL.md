# 人评协议（阶段 5，v0.1）

> 数值断言能证明"渲染符合契约与设计意图"，证明不了"观众觉得像活人"。
> 本协议定义最小可行的人评流程；结果按版本公开，**失败样片保留不删**。

## v0.1 修订（2026-11-04，来自首轮试评的实测反馈）

1. **片源必须带音轨**。v0 的 6 段成片无声——没有声音就评不了"口型与发音对
   得上吗"，这是协议设计缺陷（问卷题目超出了评审者实际拥有的感知通道）。
   修复：`tools/tts.py` 产音轨（缺省 `zh-CN-XiaoxiaoNeural`），`say --audio`
   自动按音频实测时长对齐音节速率并混流。**对齐口径诚实声明：总时长一阶对齐
   （音节总数 ÷ 音频秒数），不是逐音素对齐**——评审第 1 题应按"整体节奏对不对"
   打分，逐字微错位不扣分。
2. **评审口径改为：单人口评（作者本人）为常规检查**；≥3 人盲评保留为
   可选增强，仅在需要对外宣称质量结论时执行。依据：作者盲看 v0 的 6 段
   双模式成片**肉眼无差别**——模式对比评审取消（该结论本身入库：pinyin 与
   estimated 的差异低于肉眼阈值，与 2.5D A/B 的"低于可辨阈值"同构）。
3. n=1 的结果一律标注"参考"，不写"通过/未通过"的统计结论；定位缺陷、
   记录帧号的功能不变。

## 片源

- 每次评审取 **2 段 4~6s 成片**（带音轨）：陈述句 + 强调或疑问句，同一角色（no4），
  `--motion --coarticulate --shot medium`，音轨 `tools/tts.py` 同句生成。
- 生成：`python tools/eval_kit.py build --date <date>`（无声对比模式已弃用，
  工具保留作回归）；带音轨的单片直接用：
  `python tools/tts.py "<文本>" -o out/tts.mp3 && python tools/codeavatar.py say no4 "<文本>" -o out/clip.mp4 --motion --coarticulate --shot medium --audio out/tts.mp3`

## 问卷（每段 4 题，5 分制）

1. 口型与声音的**整体节奏**对得上吗？（1=明显错拍，5=自然同步；逐字微错位不扣）
2. 人物看起来"活"吗？（眼神/眨眼/头部微动）——1=木偶，5=自然
3. 情绪读得出来吗？（强调/疑问的区分）——1=读不出，5=明显
4. 有一眼假/出戏的瞬间吗？（开放字段，记录秒数/帧号）

## 判定

- 单人口评：**不下统计结论**。总分 ≥3.5 → 记"参考：可用"；低于 → 记录最差
  片段与秒数，转成缺陷单（evidence 进 ROADMAP 记录），**不删片**。
- 多人盲评（如执行）：题均分 ≥3.5 且第 1 题 ≥4.0 → 该配置通过本轮。

## 执行与留痕

- 单人：结果写 `docs/eval/<date>.md`（评分 + 片源 hash + 音轨 engine/voice +
  结论），`tools/eval_score.py` 支持 n=1（自动标注"参考"）。
- 多人（可选）：评审者 ≥3 人（含作者外 1 人），盲序发放，`key.json` 不外发。
- 当前状态：**待作者单人口评**（带音轨成片已就绪）。
