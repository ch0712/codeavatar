# 纯代码驱动数字人：方案与任务拆解

> 状态：方向提案 / 评审基线。目标是把“能生成 SVG 并输出口播”推进到可评测、可迭代、可复现的高表现力数字人系统。这里的“纯代码驱动”指角色的可见几何、材质、表演和合成由可审计的参数化场景生成；允许用生成式 AI 辅助角色概念设计、参考稿与离线资产建议，但运行时不依赖真人视频、神经口型替换或不透明黑盒表演模型。是否允许 AI 生成底图应明确为构建期可选工具，而不是把它混同为运行时依赖。

## 1. 目标、边界与成功标准

目标不是“参数更多”，而是让观众感到角色在听、在想、在说、在回应。质量由四个维度共同决定：身份与造型稳定；语音与口型/节奏一致；情绪和意图可读；动作、镜头、灯光与合成有审美。几何真实度不能单独代表表演质量。

第一阶段维持插画/风格化角色；不承诺仅凭任意扁平设定图恢复图中不存在的背面、遮挡结构、材质与真实三维体积。对生成底图采取角色设计 brief、正交参考视图和部件语义标注的组合；单张图自动重建只能作为候选草稿，必须报告置信度与不可恢复信息。最终仍可由代码控制所有运行时表演与渲染。

成功标准在建立基线后量化，不凭主观宣称“最真实”：
- 身份：不同情绪、角度、镜头下关键脸部比例/配色稳定；遮挡和部件拓扑无跳变。
- 口播：静音辨识说话节奏与重音；有声时音素视觉对应、闭唇音闭合、停顿和句尾收势可信。
- 表演：盲测能区分意图/情绪，表情变化有铺垫、峰值、回落，不是持续夸张摆动。
- 视觉：构图、轮廓、明暗层级、细节密度适配目标画幅；无穿帮、闪烁、轮廓破损。
- 工程：同输入、版本、种子可复现；失败可定位；CLI 可供外部工具组合调用；资源和授权可发布。

建立基准角色、脚本/音频集、参考帧与盲评流程后再冻结阈值。机器指标（同步误差、几何越界、闪烁、渲染耗时）与人评（身份、自然度、情绪可读、审美）并行，不能用单一分数替代。

## 2. 现有方案的根本风险与待验证假设

1. **把单张扁平图当成完整角色资产**：单图不含隐藏面和遮挡关系。自动追踪只能分割已有颜色块，无法推断正确拓扑；结构误差会沿眼、鼻、口、头发全部传播。必须区分“描摹”与“重建”，提供结构化角色输入、视图补充、置信度和可编辑修订点。
2. **先定参数再找表演**：固定 16 个连续数值与六个 viseme/五种 mood，容易有参数耦合、语义空洞、范围冲突和组合爆炸。连续值不等于自然表演。需把低层几何控制与高层意图/动作单元分层，约束参数、定义组合规则和可扩展版本契约。
3. **口型只是几个静态形状**：六个标签无法直接覆盖协同发音、过渡、闭唇、静音呼吸、语速、重音、语言差异。单帧可分不等于时间上可信。需要音频/文本时间轴、音素或 viseme 对齐、共发音窗口、可选音频特征修正、确定性时间采样，并明确无音频模式。
4. **情绪表是姿态偏移**：眉眼嘴的静态偏移易成为“表情贴纸”。情绪应由意图、唤醒度/效价、强度、说话行为共同驱动，包含 onset/hold/release、微表情/视线/头动及个体风格，并避免所有情绪共用一套幅度。
5. **2D 参数形变的真实感上限**：纯 SVG 平面缩放无法自然表达侧转、透视、遮挡、体积光影与颈肩联动。必须选择并验证视觉路线：高质量 2.5D 分层（深度、遮挡、视差、受控视角）作为近期主线；几何/材质可程序化。若未来探索纯代码 3D，应作为独立基准分支，与 2.5D 同角色对比，不能把伪 3D yaw 当真实转头。
6. **过度自动化但缺少纠错环**：零人工建角如果没有可视化预览、局部重描、拓扑检查与验收回路，失败会被静默固化。自动化必须输出诊断、置信度、预览和可重复编辑数据；将人工校正成本纳入指标。
7. **效果验收偏静帧/几何**：单帧 diff 和比例误差不能衡量表演。增加时间序列测试、音画同步、边缘稳定、遮挡连续性、跨镜头身份及真人评审；参考图像像素差只适用于颜色/布局对齐后的局部诊断。
8. **职责与契约可能漂移**：CLI、Python 工具、TS 类型、角色 JSON 和 Remotion 渲染间若存在多份事实源，会产生隐式转换、路径假设和兼容问题。明确 schema、版本迁移、严格校验、输入输出协议、依赖图和兼容策略；生成阶段与渲染阶段边界清楚。
9. **可复现与开源体验欠缺**：依赖锁定、跨平台安装、资源许可、示例素材、CI 与“从零生成第一条视频”需验证。非确定性步骤需显式标记并可固化产物；CLI 返回结构化错误和退出码。
10. **评价目标必须诚实**：纯代码本身不是质量保证。以实际目标画幅和内容做盲评，公开能力边界、失败例和性能预算；不以“超越顶级 AI”等不可证伪表述作为工程验收条件。

## 3. 目标架构

```text
角色 Brief / 参考稿 / 可选多视图
              ↓
资产构建器：分区、语义部件、深度/遮挡、几何拟合、材质
              ↓  角色包 + schema 版本 + 诊断/预览/置信度
表演编排器 ← 文本/音频/时间戳/情绪意图/动作轨
              ↓  可采样、可插值、可复现的 Performance
渲染器：角色 rig + 镜头/灯光/背景/字幕/合成
              ↓
独立帧 / 透明序列 / 口播视频 / manifest / 报告
              ↕
质量闸门：结构、时序、同步、视觉回归、基准评测
```

建议先模块化单体，避免过早拆服务。角色资产包是构建和渲染的稳定接口；core 定义 schema、默认值、插值、采样及迁移；CLI 编排工具但不复制业务逻辑；studio 负责预览和成片。所有步骤保存 manifest（工具版本、资产 hash、输入、选项、种子、输出 hash）。

### 角色资产

从一份可版本化 schema 派生类型与 JSON Schema/校验逻辑；按语义部件组织，而非只靠命名约定。每个部件描述几何、局部坐标、锚点、层级/深度、遮罩、形变能力和材质。角色包附带风格档案、默认 rig 参数、视角范围、参考图、来源与许可证。初期采用分层矢量 + 深度/遮挡 + 参数化网格形变；拓扑不确定时提示用户修订，不静默生成“看似成功”的脸。

### 表演数据

分为音频时间轴、语言/音素或 viseme 轨、韵律特征、语义意图/情绪轨、头眼手势轨、最终低层 rig 曲线。统一时间单位和采样规则；关键帧可稀疏存储，任意帧确定性求值。为每种 track 定义优先级、叠加/混合方式、限幅与冲突诊断。语音分析可插拔；基本几何和渲染无网络依赖。

### 渲染输出

渲染接口与 Remotion 解耦为核心采样器 + renderer adapter。支持透明背景/绿幕/背景、横竖画幅、帧率、音轨、字幕与独立口播视频。音频、字幕、角色表演共享统一时间基准；输出文件旁有 manifest 和诊断报告。渲染失败应可从给定帧与参数复现。

## 7. 已核实的当前实现缺陷（2026-10-31 代码审查）

下列结论来自代码阅读，运行时基线尚未执行；避免把推断写成实测结果。

### P0：直接阻断可用性与承诺

- `tools/codeavatar.py` 的 `grid` 与 `render` 无条件调用 `systemd-run`，并用 `MemoryMax` 限制资源。该入口在原生 Windows 不存在；当前 CLI 因而不是跨平台入口。README 没有标注限制。
- Python CLI 以根目录相对路径定位脚本/角色数据，但把用户输入 sheet、props 路径原样转交子进程/`open()`；从其他工作目录调用时行为不明确。外部工具集成需要明确相对路径基准和 cwd 语义。
- `grid`、`render` 通过 `npx remotion` 运行，但根 `package.json` 没有定义可靠的跨平台命令入口；输出目录和资源上限也硬编码在 Linux 包装里。
- README 示例引用 `examples/perf.json`，仓库文件清单中没有该文件；当前无法按文档直接复现口播示例。
- npm workspace 根与 `@anchor/core`、`@anchor/studio` 均标为 `private`，根 license 为 `UNLICENSED`。这与“开源维护、第三方 CLI 集成”的目标冲突，须在公开复用前补齐授权与发布策略。

### P1：效果根因与系统性风险

- `Perf` 是已经逐帧生成的帧数组，不是从音频/文本自动分析出来的表演；`poseAt()` 负责映射现成的 viseme、口腔包络、重音、手势和视线字段。现有链路缺少音频/文本到这些字段的生成实现与可复现样例。
- 情绪标签由固定手势类别映射，并在视频最后 0.9 秒强制切为“轻松”；同一手势窗口内姿态固定为情绪预设加短交叉，不支持独立的意图、强度、起伏、保持和释放轨道。
- 视线和头部摆动包含按时间正弦驱动的 sway/glance，另有固定 seed 的随机扫视/眨眼表。它们可以重放，但没有对话对象、语义、停顿和音频韵律条件，可能形成与内容无关的动作。
- `Pose` 注释范围与实际预设不一致：brow 声明 0..1 却含负值；browIn 声明 0..1 却含 1.15；lid 注释范围也没有被集中定义为机器可校验契约。渲染器自行 clamp 部分参数，其余参数采用不同规则，容易产生文档、控制器和视觉行为分歧。
- README/spec/core 注释存在旧路径 `src/anchor-code/...`；README 承诺的包边界、确定性及自动建角尚需结合边界脚本和真实运行验证。
- `FaceTraced` 将演示角色静态 import 后用联合类型锁定角色键；新增角色可能需要改源码/重建包，和“构建阶段生成角色、第三方 CLI 使用”的数据驱动扩展目标相冲突。
- 当前主要渲染实现是 SVG 分层与局部几何变形。固定宽度视线移动、平面缩放式 yaw 和单一 head transform 无法表达通用的深度、遮挡和体积变化；应通过同角色视觉原型比较来确定 2.5D 结构，不能靠增加参数掩盖表示能力边界。

### 数据流现状（静态代码追踪）

```text
sheet PNG → sheet_gate.py → trace_design.py auto → 角色 JSON
                                      └→ split_eye_layers.py 原地修改角色 JSON
perf JSON → codeavatar.py props 合并 → Remotion Presenter
           → perf.ts poseAt(frame) → FaceTraced SVG → Remotion render → 视频
```

`grid` 走 `VisemeGrid` + `gate_mouth.py`。当前 CLI 把构建、诊断和渲染串在一个 Python 入口；TS core 负责角色渲染/表演映射，但 schema 并非跨 Python/TS 共享的机器校验源。角色构建通过多步原地写最终文件，缺少事务性输出与中间产物 manifest；失败时需检查是否留下半成品。

## 8. Linux 与 Windows 跨平台验收（P0，非后续优化项）

Linux 和 Windows 都是一等开发、创作、CI 和发布平台。任何核心功能不得只在其中一侧提供；支持版本在 README 明确（例如 Windows 10/11 与受支持 Linux LTS，具体基线在 CI 盘点后冻结）。

### 设计要求

- 用 Python `subprocess` 的参数数组直接启动子进程，不经 shell 拼接命令；路径统一使用 `pathlib`，所有用户给出的相对输入都按“调用者当前目录”或明确的项目根规则解析并写入 CLI 文档。
- 移除对 `systemd-run`、bash-only 脚本和 GNU-only 命令的运行时依赖。内存/并发限制作为可选配置：能检测平台时采用平台实现；无法实施时给出明确告警或拒绝严格限制选项，不能假装限制已生效。
- Python/Node 子进程使用当前解释器、锁定依赖和可定位的本地 Remotion CLI；不要依赖下载型 `npx` 在运行时悄悄获取不确定版本。
- JSON 参数使用稳健编码传递，避免 Windows 命令行长度/引号差异；大 props 使用临时 JSON 文件或标准输入，并确保临时文件可清理、渲染日志可追踪。
- 输出路径、文件名、Unicode、空格、盘符、反斜杠、只读目录和缺失目录均有明确行为；覆盖输出需要明确选项，临时/失败产物不污染角色事实源。
- 媒体编码器与字体需有可检测、可解释的依赖检查；支持的编码器、字幕字体回退、透明输出限制和安装方式在文档公开。
- 统一 CLI 的错误格式、退出码、stdout（机器可读结果）与 stderr（诊断），使 PowerShell、bash、CI 和第三方程序均可可靠调用。
- 提供一套平台无关的 Python CLI 封装；如保留 shell 脚本，仅作为薄 wrapper，Windows 同时提供 PowerShell 或 npm 跨平台入口。

### 本次落地的两处修复（有实测证据）

1. **渲染浏览器显式解析**（`tools/codeavatar.py` 新增 `find_browser()`）：
   Remotion 默认从 storage.googleapis.com 下载 Chrome Headless Shell，网络受限环境**永久挂起**
   （实测 >10 分钟零输出）。现在按 `CODEAVATAR_BROWSER` → `node_modules/.remotion` 缓存 →
   系统 Chrome/Edge 的顺序显式探测并传 `--browser-executable`；找不到时打印告警并回退默认下载行为。
2. **`render --props` 的 perf 接线修复**（`cmd_render`）：
   原实现把 perf.json 字段平铺进顶层 props，而 `Presenter`/`calculateMetadata` 读的是 `props.perf`，
   perf 因此**静默丢失**——成片恒为 90 帧静态中性脸（实测修复前 3.0s 无表演，修复后 1.0s 有表演）。
   现在接受裸 Perf（挂到 `props.perf`）或含 `perf` 键的完整 props 两种形式。
